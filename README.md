# MIL-DRAFT

אפליקציה עובדת לפי מוקאפ MIL-DRAFT: חדר בחירה, לוח דראפט חי, דף מגבש, תמונת מצב וייבוא אקסל.

## הרצה
    npm start            # http://localhost:3000   (PORT=... לשינוי פורט)

אין תלויות הרצה (Node בלבד). `xlsx` משמש רק את הדפדפן (הועתק ל-`public/xlsx.min.js`).

## איך זה עובד
- **כניסה בשלושה שלבים:** חיל (רגלים / מודיעין / קשר / משאבי אנוש / פיתוח) ← יחידה ← תפקיד. במשאבי אנוש היחידות הן משאבי אנוש / מטה / ראש אכ״א, ובפיתוח תפקידי המערכת.
- **משתמשים:** 7 משתמשי דמו (שלישות ×3 חילות, מפקד/ת הכשרה, מגבשים ×3). ההרשאות לפי הסיווג.
- **דראפט:** 4 סבבים, סדר מתחלף (snake), ללא שעון ולחץ זמן. (אופציונלי: `CLOCK_SECONDS=<שניות>` מפעיל שעון, ויחידה שלא בוחרת בזמן מקבלת בחירה אוטומטית). יחידות ללא משתמש מחובר בוחרות אוטומטית; בחירה אוטומטית גם כשהשעון נגמר.
- **חי:** כל שינוי מתפשט לכל הדפדפנים דרך SSE. אפשר לפתוח כמה משתמשים במקביל.
- **מגבש:** שליחת התרשמות מעדכנת את תיק המועמד מיד בחדר הבחירה.
- **ייבוא/ייצוא:** xlsx/csv, מיפוי עמודות, בדיקת תקינות, תבנית להורדה.
- **נתונים:** נשמרים ב-`data/state.json`. מחיקת הקובץ (או `POST /api/factory-reset`) מחזירה לנתוני הדוגמה.

קבצים: `server.js` (API+SSE+לוגיקת דראפט), `config.js` (יחידות, מכסות, תנאי סף), `public/` (ממשק).

## התקנה כאפליקציה בטלפון (PWA)
- **אנדרואיד / Chrome:** פותחים את הקישור ולוחצים על ״התקנה״ (או תפריט ⋮ ← ״הוסף למסך הבית״).
- **אייפון:** פותחים ב-Safari ← כפתור השיתוף ← ״הוסף למסך הבית״.
- הגרסה הסטטית (GitHub Pages) עובדת גם בלי חיבור. גרסת השרת (Render) צריכה חיבור.


## חדש: תוצאות, השוואה, הגדרות, CI
- **תוצאות ויומן** (`#/results`): שיבוצים, לפי יחידה, ללא שיבוץ ויומן פעילות; ייצוא Excel / CSV / הדפסה ל-PDF.
- **חיפוש והשוואה** בחדר הבחירה: חיפוש לפי שם/מספר, והשוואת 2-3 מועמדים זה לצד זה (הצגה בלבד, ללא ציון מסכם).
- **הגדרות דראפט** (`#/settings`, מנהל/ת מערכת): מספר סבבים, סדר מתחלף/רגיל, וכללי שיבוץ אופציונליים לבחירה ידנית.
- **CI**: `bash scripts/ci.sh` (גם ב-GitHub Actions בכל push) בודק שה-`index.html` מעודכן ומריץ את בדיקת העשן.

## אבטחה וכניסה עם סיסמה
ברירת המחדל היא **מצב דמו פתוח** (בחירת משתמש בלי סיסמה). להפעלת הגנה אמיתית מפעילים `AUTH=1`:

```bash
AUTH=1 ADMIN_PASSWORD='סיסמה-ארוכה-123' TRUST_PROXY=1 node server.js
```
- **כניסה**: חיל ← יחידה ← תפקיד ← סיסמה אישית. הסיסמאות נשמרות מוצפנות (scrypt, מלח לכל משתמש) ב-`data/auth.json`.
- **סשן**: cookie חתום (`HttpOnly`, `SameSite=Strict`, `Secure` תחת HTTPS), תוקף 8 שעות (`SESSION_HOURS`). הכותרת `X-User` מתעלמת לגמרי במצב הזה.
- **הנפקת סיסמאות**: האדמין `a1` נוצר בהפעלה הראשונה (סיסמה מ-`ADMIN_PASSWORD`, או סיסמה אקראית שמודפסת פעם אחת ללוג). משם: הגדרות דראפט ← "משתמשים וסיסמאות" ← "הנפקת סיסמה". הסיסמה זמנית ומוצגת פעם אחת; המשתמש/ת מחליף/ה אותה בכניסה הראשונה (לפחות 10 תווים, אותיות וספרות).
- **הגנות**: נעילת חשבון ל-15 דקות אחרי 5 ניסיונות כושלים, הגבלת קצב לפי כתובת (20 ניסיונות ב-10 דקות), תגובה זהה למשתמש לא קיים וסיסמה שגויה, ביטול סשן באיפוס/שינוי סיסמה, הגנת CSRF (כותרת מותאמת + SameSite), כותרות אבטחה (CSP, X-Frame-Options, nosniff, HSTS תחת HTTPS), `Cache-Control: no-store` ל-API.
- **יומן אבטחה**: כל כניסה (מוצלחת וכושלת), יציאה, שינוי ואיפוס סיסמה נרשמים ב-`data/audit.log` ומוצגים לאדמין.
- **בדיקות**: `node scripts/auth-test.cjs <url> <adminPassword>` (רצות גם ב-CI).

מה שעדיין תלוי בסביבה שלכם ולא ניתן לפתור בקוד: אירוח מאושר ברשת סגורה, HTTPS, הצפנת הדיסק, גיבויים, אישור אבטחת מידע, והתחברות ל-SSO/ספק זהות ארגוני אם יהיה.
